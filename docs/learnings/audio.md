# 音まわりの学び

`LEARNINGS.md` から切り出した項目です（2026-10-06）。`utils/audioManager.ts` を直すとき、音の切り替えや大きさを確かめるときに読みます。
書き方は LEARNINGS.md と同じ（1項目 1〜3行、太字で主張を先頭）。新しく学んだことはここに足します。

- **音の切り替えは、`window.Audio` を差し替えて再生中の要素を記録すると、耳なしで確かめられる。** 画面の状態（プレイ・FEVER・リザルト）と「止まっていない曲」の組を時系列で並べる。最初に本物のクリック（`computer` の left_click）を1回入れないと音は始まらない。
- **音の大きさは OfflineAudioContext で測れる（耳がなくても数字で比べられる）。** 開発サーバーのページで `globalThis.__dopaAudio` の `ctx` と `masterGain` を OfflineAudioContext のものに差し替え、`playXxx()` を呼んで `startRendering()` し、50ms ごとの RMS の最大（dB）とピークを出す。曲は `decodeAudioData` して同じ計算をする。2026-10-06 の値：曲は4つとも平均 -14dB、打鍵音 -8.6dB、調整前の成功音（単語クリア・コンボ・レベルアップなど）は -15〜-18dB で打鍵音より小さかった。調整後は -6〜-10dB。測ったあとは必ずページを開きなおす（差し替えた ctx が残る）。
- **曲のファイルから「区切りのよい頭の部分」を探すときは、開発サーバーで `/_inbox/xxx.mp3` を fetch して OfflineAudioContext で decode し、0.05秒ごとの RMS（dB）を並べる。** -30dB 前後まで落ちて 0.3秒以上つづく所がフレーズの終わり。音の出るアプリのページではなく、`/_inbox/_view.jpg` など絵だけのページで実行する（曲が鳴らない）。
- **「新しい曲に替える」処理は、替える相手だけでなく「いまの曲以外ぜんぶ」を止める形にする。** FEVER 中にプレイが終わると「プレイ曲へ戻す → すぐ止める → リザルト曲」と続けて呼ばれ、1つ前の曲だけを消す作りでは FEVER の曲が鳴りつづけた（`audioManager.ts` の `fadeOthers`）。
- **【重大】開発サーバーでページを開いたまま `utils/audioManager.ts` を書きかえると、audioManager が作りなおされ、前のものが鳴らしていた曲が止まらずに新しい曲と重なる（ユーザー指摘「複数の曲が同時に流れている」）。** 作りなおす前に `globalThis.__dopaAudio` 経由で前のものを `dispose()` するようにした。`import.meta.hot.dispose` は効かない（Vite は、差し替えを受けとる側のモジュールの dispose しか呼ばない。途中のモジュールは呼ばれない）。音や常駐するもの（タイマー、Audio 要素）を持つシングルトンは、同じ形にする。
- **「切り替えの確認」は、新しく開いたページだけでなく、開発中の自動更新（HMR）をはさんだ場合も見る。** 本番ビルドと新しいページだけで確かめて「1曲しか鳴っていない」と報告し、ユーザーが実際に聞いていた状態（開きっぱなしの開発ページ）を見落とした。音量まで見るには、`AudioNode.prototype.connect` を差し替えて Audio 要素と GainNode の組を記録する。
- **ユーザーが「重なって聞こえる」と言ったら、アプリの中だけでなく「音を出しているページがほかにないか」を先に数える。** コードの中を2回調べて別の原因（HMR）を直したが、聞こえていた音の出どころは別のタブだった。
- **開発サーバーのページで `await import('/utils/audioManager.ts')` をすると、アプリが使っているものとは別の audioManager が作られ、アプリ側のものが片づけられる（曲が止まり、`musicWanted` が null になる）。** アプリの状態を見るときは `globalThis.__dopaAudio` を使う。import でよいのは、状態を持たない純粋な関数のモジュールだけ。
- **低い音（サイン波 170→45Hz の「ドン」）は、小さな音量でもピークとリミッターを大きく動かす。** 音量 0.7〜1.0 で足したらコンボ音のピークが 4.9 になった。0.2〜0.4 に下げた。
- **タブが裏に回って戻ったとき、曲が自動で戻らなかった（ユーザー指摘）。** 戻ったときの処理が「音の出口（AudioContext）が running のときだけ流す」で、止まっていると何もしなかった。再生がことわられたときのやり直しもなかった。いまは `wakeMusic` が出口を `resume()` してから流し、ことわられたら 0.7秒おきに5回までやり直す。`focus` と `pageshow` でも呼ぶ。
- **Claude のブラウザ（Browser pane）も、裏に回した Chrome のタブも、本物の `visibilitychange` を起こせない**（pane はタブを切り替えても `document.hidden` が false のまま。Chrome の操作用タブは最初から hidden）。確かめるときは `document.hidden` を差し替えてイベントを自分で投げ、あわせて `ctx.suspend()` と「`play()` を1回だけ失敗させる」で、実際に起きうる状態を作る。最後はユーザーに実機で見てもらう。
- **ページを開いた直後（再読み込みのあと）に曲が鳴るかは、ブラウザの自動再生の決まりしだい。** アプリは開いた時点で音の出口を作って流そうとする（`playMusic` の中の `init()`）。許されればすぐ鳴り、許されなければ最初のクリックかキー入力で鳴る。Claude のブラウザは操作なしでも鳴る（`userActivation.hasBeenActive` が false でも ctx は running）ので、Chrome での挙動の確認にはならない。
- **メロディが上がっているか下がっているかは、区間を 0.05〜0.1秒ごとに切り、半音ごと（MIDI 60〜100）の強さを Goertzel で出して、いちばん強い音の番号を並べると見える（2026-10-07）。** きれいなアルペジオは 60 61 64 68 73 … 100 のように数字がそのまま上がる。ベースやドラムが重なった所は数字がばらつくので、当てにしない（低い音まで範囲に入れると、ベースばかり拾う）。
- **切り方・速さ・フェードをかけたあとの音をユーザーに聞いてもらうときは、ブラウザの OfflineAudioContext で書きだして WAV にし、手元だけの小さな受けとりサーバー（node の http、127.0.0.1）へ POST して `_inbox/` に保存する。** MP3 のままでは、頭の余白・途中で切る位置・倍速を聞いてもらえない。HTML の聞きくらべページは、横のパネルでは使われなかった（「音だけ再生できるようにして」とユーザー指示）。音のファイルをそのまま送る。
