# 画面を表示領域に収めるときの学び

`LEARNINGS.md` から切り出した項目です（2026-10-07）。画面の収め方（`FitScreen`・`StageShell`・スクロール領域）を直すとき、確かめるときに読みます。
書き方は `LEARNINGS.md` と同じです（1項目 1〜3行、太字の主張を先頭に）。

- **拡大するアニメ（scale(9) など）はスクロール領域を広げる。** リザルトのランク発表で横スクロールバーが出た。スクロールさせる入れ物には `overflow-x-hidden` と `.dopa-scroll`（バー非表示）を付ける。
- **中身を縮めて収めるとき「幅が広がれば低くなる」とは限らない。** 正方形のカード（図鑑）は幅が広がると高くなる。`FitScreen` は倍率ごとに測りなおす二分探索にしてある。再計算は rAF ではなく `setTimeout`（裏のタブやプレビューでは rAF が止まる）。
- **メニュー系の画面は `components/FitScreen.tsx` に入れる（2026-10-06 ユーザー決定：表示領域 1280x720 以上でスクロールなし、操作ボタンは必ず見える位置）。** 中身は children、もどる・決定などのボタンは `footer` に渡す（画面下に固定）。新しい画面もこの形で作る。確認は `.dopa-scroll` の `clientHeight` と、その最初の子の `offsetHeight × scale` を比べる。1280x720 での倍率は 0.73〜0.93、1920x940 では全画面 1.0。
- **飛んでいく・回る絵（割れたカプセル、集中線）は、見えなくなったあともスクロール領域を広げる。** `overflow-hidden` の入れ物で切る。`FitScreen` で縮んでいる画面は、もとから `scrollHeight` が「縮める前の高さとの差の半分」だけ大きい（1280x720 のガチャで 602 → 623）ので、変更前の値と比べて判定する。
- **表示領域の高さが 720 未満のときは、同じページを iframe の中に開いて縮める（`components/StageShell.tsx`、2026-10-07 ユーザー決定）。** Windows の「文字の大きさ」225% を Chrome はページ全体の拡大として扱い、FHD でも表示領域が約 853x330 になる（`HKCU:\SOFTWARE\Microsoft\Accessibility` の `TextScaleFactor` で読める）。枠の中は高さ 720 の本物の画面なので、vh・vw・`md:` などはそのまま効き、ゲーム本体は変えていない。切り替えは読みこみ時に `index.tsx` で1回だけ決める。出題文字は枠の中では §3.1 のまま（160px / 96px）で、実寸はふつうの PC と同じになるまで縮む（ユーザー了承）。確認するときは `document.querySelector('iframe').contentWindow` の中を測り、キーは外側の `window` に送っても中へ渡る。Browser pane が隠れていると `innerHeight` が 0 になるので、0 のときは等倍にしてある。
