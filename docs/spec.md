## 3. 【最重要要件】出題文字のサイズ（ロービジョン配慮）

元アプリ highfive_7979 は「視力の弱い人でも読めるよう、出題文字をできるだけ大きくする」がコンセプト。highfive_dopa でも**出題文字のサイズはオミット不可**とする。それ以外（配色・光の点滅など）は派手な演出を優先する（§2-7）。

### 3.1 既存のサイズ（下限）

`components/GameScreen.tsx` より。

| 要素 | 現状 |
|---|---|
| 出題（かな） | `text-[5rem] md:text-[8rem] lg:text-[10rem]`（最大 160px 相当）。10文字以上は `4rem / 6rem` |
| ローマ字 | `text-5xl md:text-7xl lg:text-8xl`（最大 96px 相当）、等幅フォント、字間広め |
| 出題エリア | 画面高さの50%以上（`min-h-[50vh]`） |

### 3.2 ルール

1. **必須**: 出題かな・ローマ字の表示サイズは 3.1 を下回らない。演出中（ズーム・縮小アニメ・カットイン中など）も、読ませるタイミングでは下限サイズ以上で表示する
2. **必須**: 出題エリアの広さ（画面高さ50%以上）を、キャラや UI で削らない
3. **追加**: 「もじの大きさ」設定（ふつう＝既存サイズ／おおきい／さいだい＝画面幅いっぱい）を用意
4. **任意（推奨のみ）**: 演出が出題文字を長時間まるごと覆い隠さないこと。揺れ・色変化・重なりそのものは許可

### 3.3 確認方法

- 各画面幅（スマホ横・タブレット・PC）で、演出 MAX 時も出題文字が 3.1 のサイズ以上で出ていることを確認
- 弱視の当事者・支援者にテストプレイを依頼する（P4 で実施）

## 4. 既存（highfive_7979）から踏襲するもの

- **技術構成**: React 19 + TypeScript + Vite、lucide-react、Google Fonts（Mochiy Pop One / Zen Maru Gothic / JetBrains Mono）
- **難易度5種**: かんたん／ふつう／むずかしい／マスター／かいわ（単語 約1,100語、`constants.ts`）

- **サウンド**: Web Audio（打鍵・ミス・決定・キャンセル・ファンファーレ）、音量 OFF/小/中/大
- **開発者設定**: ローマ字優先設定、単語JSON入出力、フォント切替、localStorage保存

## 6. プレイ中の演出・ルール

※守るのは §3 の出題文字サイズのみ。それ以外は派手さ優先。

### 6.1 打鍵ごとの「ジュース」演出（最重要）

- 正打鍵ごと: パーティクルがはじける、打った文字が画面外へ飛んでいく、画面全体がフラッシュ
- コンボに応じて画面シェイク・ズーム・色反転・背景スクロール速度・発光が段階アップ（出題文字ごと揺らしてよい）
- 打鍵音はコンボが続くほど音階が上昇（1オクターブでループ）
- 単語クリア: 「GREAT!」「PERFECT!!」が画面中央に回転しながら出る（ノーミスで PERFECT）。次の出題はすぐ出し、テンポを落とさない
- ミス: 「ガシャーン」効果音＋画面の赤フラッシュ＋ラビッドパがずっこける。既存の大きな「X」も残す

### 6.2 コンボ段階【仮】

| コンボ | スコア倍率 | 演出段階 | ラビッドパ |
|---|---|---|---|
| 0–4 | ×1.0 | 通常 | ふつう |
| 5–11 | ×1.2 | パーティクル増量 | ノリノリ |
| 12–24 | ×1.5 | 画面シェイク＋背景加速＋集中線 | さけぶ・オーラ小 |
| 25–49 | ×2.0 | 色反転＋ズームパルス＋フラッシュ | 踊る・オーラ大 |
| 50+ | ×3.0 | 最大演出 | 覚醒衣装 |

段階が上がるとラビッドパが画面中央へ飛び出すカットイン、10コンボごとに画面上部の帯のカットインが出る。

### 6.3 フィーバー

- ゲージは 100 で満タン。正打鍵ごとに +5、単語クリアで +10。**満タンで FEVER TIME（10秒）**【仮】。低学年でも1プレイのうちに届く量にしてある
- FEVER中: 画面全体が虹色、BGM倍速、スコア ×2、ラビッドパが FEVER ダンス
- ミス時（やさしめ）: コンボ0、ゲージは 4分の3 残る。**FEVER中のミスでFEVERは終わらない**

### 6.4 ボーナスタイム（ポイント倍）

FEVER（コンボで溜めるスコア倍）とは別に、運で起きる「ポイント倍」タイム。

- プレイ中、一定確率（初期 10%【仮】）で **ゴールデンワード**（金色に光る単語）が出現
- ゴールデンワードをクリアすると **10秒間 ボーナスタイム**：獲得スコアとコインが ×2
- FEVER と重なると最大 ×4（「W ボーナス!!」専用演出）
- 出現率・継続時間はスキルツリーで強化可能

### 6.5 ヒント

既存踏襲。ヒント表示中もコンボは維持（やさしめ方針に合わせる）。

### 6.6 相棒キャラ「ラビッドパ」

元デザイン: `docs/character/reference.jpg` ／ リグ: `docs/character/rabidopa.js` ／ デモ: `docs/character/preview.html`（`rabidopa.gif`）

- **見た目**: 丸みのある寸胴ボディ、左耳は立ち・右耳は先が折れる、大きな丸い目、ほっぺ、白いおなか、短い足、太めのアウトライン
- **カラー**: ピンク（本体 #F7A8C4 / 影 #EC89AE / 明部 #FDE1EB / 線 #7A2E55 / ほっぺ #F0607F）。ブルー（元デザイン色）はガチャのカラー違い衣装候補
- **向き**: 正面固定。体の向き変更は不要

#### リグ（pose パラメータ）

`renderRabidopa(pose)` に以下を渡すと、その姿勢の SVG を返す。毎フレーム pose を計算して描き直すことで動かす。

| パラメータ | 内容 | 例 |
|---|---|---|
| `expression` | 表情 normal / happy / shout / miss | `'shout'` |
| `ears.l / ears.r` | `rot`: 角度（度）、`len`: 伸び倍率 | `{rot:20, len:1.5}` |
| `arms.l / arms.r` | `null`＝おなかを抱える。`{ang, len, bend}`＝角度（上が＋）・長さ px・しなり px で**ゴムのように伸びる腕** | `{ang:60, len:170, bend:30}` |
| `legs.l / legs.r` | 足の伸び px。伸びた分だけ体が持ち上がる（片足だけも可） | `150` |
| `squash` | 体のつぶれ／伸び（体積を保つ） | `0.88` |
| `tilt` | 体の傾き（度） | `-22` |

#### アニメーション（v1.0）

| 名前 | 長さ | 動き | 使う場面 |
|---|---|---|---|
| 待機 | 2.4秒ループ | ゆっくり弾む、耳がゆれる | 待機・コンボ 0–9 |
| 正打鍵 | 0.6秒 | つぶれて弾み、両腕を伸ばして万歳、耳がピン | 正打鍵ごと |
| さけぶ | 0.8秒ループ | 星目、耳が1.5倍に伸びる、長い腕をぶんぶん | コンボ 25 以上 |
| FEVER ダンス | 0.8秒ループ | 左右の足を交互に伸ばし、体を揺らし、腕と耳が波打つ | FEVER 中 |
| ジャンプ | 1.2秒 | 足が最大150px伸びて大ジャンプ、腕も伸びる | 単語クリア |
| ずっこけ | 1.2秒 | 傾いて片足が跳ね上がり、耳が垂れ、腕がばたつく | ミス |

- **段階変化**（§6.2）: オーラ・衣装は SVG の上に重ねるレイヤーとして追加（ガチャ衣装も同じ仕組み）
- **配置**: 画面の左下または右下が基本。演出時は手足を伸ばして画面中央へ飛び出してもよい（§3.2-2 の出題エリアの広さは削らない）
- 実装は React コンポーネント `<Rabidopa anim="fever" />` とし、内部で requestAnimationFrame で pose を更新

## 7. スコア・ランク・報酬

### 7.1 スコア計算【仮】

```
打鍵スコア  = 10 × コンボ倍率 × FEVER倍率 × ボーナスタイム倍率
単語クリア  = 50 ＋ スピードボーナス（目安時間より速いほど最大 +50）
ノーミス単語 = +30（PERFECT）
```

ミスによる減点はなし（コンボが切れることがペナルティ）。

### 7.2 ランク

C / B / A / S / SS / SSS / ∞。しきい値はモード × 難易度ごとに設定（実プレイで調整）。∞はほぼ届かない演出用。

しきい値【仮】（v0.14。`utils/gameRules.ts`）は「基準 × 難易度の係数」。ランクはゆるめにつけ、はじめての子でも C ばかりにならないようにする。

| モード | 基準（C / B / A / S / SS / SSS / ∞） | 係数（かんたん / ふつう / むずかしい / マスター / かいわ） |
|---|---|---|
| 練習 | 0 / 800 / 1400 / 2000 / 2800 / 3600 / 6000 | （下の固定値） / 1 / 1.6 / 2.4 / 1.2 |
| アーケード | 0 / 400 / 1200 / 3000 / 5000 / 8000 / 20000 | 0.8 / 1 / 0.8 / 0.65 / 0.9 |

- 練習 × かんたん だけは固定値: 0 / 560 / 980 / 1400 / 1700 / 2000 / 2300（1問が 1〜3打で点の幅がせまいため）
- アーケードは、長い単語ほど単語クリアの点が入る回数がへるので、むずかしいほど係数を小さくする

### 7.3 プレイ後の獲得物

| 獲得物 | 用途 | 計算【仮】 |
|---|---|---|
| コイン | ガチャ（見た目系） | スコア ÷ 100（ボーナスタイム中の分は ×2）＋ あそんだごほうび 50。はじめて遊ぶ人は 100コイン持って始まる |
| 経験値（EXP） | プレイヤーレベル → スキルポイント | スコア ÷ 10 ＋ あそんだごほうび 30 |
| スキルポイント（SP） | スキルツリー（機能系） | レベルアップごとに 1SP。次のレベルまで 100＋35×(レベル−1) EXP（`utils/progression.ts`） |

通貨を分けることで「ガチャ＝見た目」「スキルツリー＝できることが増える」と役割をはっきりさせる。

### 7.4 進み方の方針（v0.14）

一般公開や収益化は考えないので、**かんたんに進み、遊ぶたびに変化があり、つぎつぎ遊びたくなる**ことを優先する。前半は遊ぶたびに変化（レベルアップ・ガチャの新しいアイテム）、後半は数回遊ぶと変化、くらいの速さにする。比較的早く全部そろってもよい。

腕前ごとの試算（一定の速さで打つ計算。1日3回、かんたん・ふつう を交互）:

| 腕前 | ガチャ全20種 | 全スキル（32SP） |
|---|---|---|
| はじめて（2秒に1打・ミス20%） | 64回 | 151回 |
| ゆっくり（1秒に1打・ミス10%） | 45回 | 72回 |
| なれてきた（1秒に2打・ミス5%） | 31回 | 37回 |

## 8. スキルツリー（機能解放）

SP を使ってノードを解放する。前提ノードを取ると次が開く3本の枝構成。

### 8.1 あそび（モード・難易度の解放）

| ノード | 内容 | SP |
|---|---|---|
| むずかしい解放 | 難易度「むずかしい」 | 1 |
| マスター解放 | 難易度「マスター」（前提: むずかしい） | 2 |
| かいわ解放 | 難易度「かいわ」 | 2 |
| ゴースト対戦 | 自己ベストのスコア推移（1秒ごと）との差を、スコア表示の上に「ゴースト +120」と出す。出題エリアには何も置かない | 3 |

### 8.2 ブースト（ゲームを有利に）

| ノード | 内容 | SP |
|---|---|---|
| FEVER延長 Lv1–3 | FEVER +1秒ずつ | 1/2/3 |
| ゴールデン率UP Lv1–3 | ゴールデンワード出現率 +5%ずつ | 1/2/3 |
| ボーナス延長 | ボーナスタイム +5秒 | 2 |
| ゲージ守り | ミス時のゲージ減少を半分に（v0.10 で減少が 1/4 になったので、1/4 → 1/8） | 3 |

| ノード | 内容 | SP |

## 10. 安全面

- **演出の優先**: 派手さを優先し、光の点滅回数・赤フラッシュなどの制限は**設けない**（§2-7）。初期値は「演出のつよさ：MAX」
- **演出のつよさ設定**: ひかえめ／ふつう／MAX を残す（ひかえめはフラッシュ・シェイク無効）。光に敏感な子や保護者が自分で選べるように
- **光の点滅の注意書き**: 一旦なし（必要になったら後から追加）
- **課金・外部通信なし**: ゲーム内通貨のみ、個人情報は保存しない（localStorage のみ）
- **休けいお知らせ**
  - 設定: OFF / 15 / 30 / 45 / 60分（初期値 30分）
  - 連続プレイ時間が設定値を超えると、プレイ終了後にラビッドパが「ちょっと休けいしよう！」と表示
  - プレイ途中では割り込まない（終わったタイミングで出す）
  - オプション（設定）画面に置き、**ロックなしで誰でも変更できる**
  - 実装（v0.12。`utils/breakTimer.ts`）: 連続プレイ時間は「続けて遊びはじめた時刻」からの経過。プレイとプレイの間が 5分 以上あいたら休けいしたとみなして数えなおす。お知らせを出したあとも数えなおす。ページを開いているあいだだけ覚えており、保存はしない

### 11.1 画面に収めるルール（v0.13）

ブラウザで遊ぶ前提。**表示領域 1280x720 以上なら、プレイ以外のどの画面もスクロールなしで収まる**こと（FHD モニター上のブラウザ＝約 1920x940 を含む）。それより小さい窓は対象外。

- メニュー系の画面（タイトル・リザルト・スキルツリー・ガチャ・ずかん・オプション）は `components/FitScreen.tsx` に入れる。高さが足りないとき、中身をまとめて縮める（FHD のブラウザでは等倍）
- **もどる・決定などの操作ボタンは画面の下に固定**（`FitScreen` の `footer`）。0.6 倍より小さく縮めないと収まらない小さな窓では、中身だけがスクロールし、ボタンは画面に残る
- プレイ画面は `FitScreen` を使わない（出題文字のサイズ §3 を変えないため）

## 12. 技術方針

- highfive_7979 のコードを highfive_dopa にコピー済み（2026-10-05。`.git`・`node_modules`・`.env.local` は除外）
- 演出: CSS アニメーション＋Canvas（パーティクル）。追加ライブラリは最小限（候補: canvas-confetti）
- レイヤー構成: 背景 → 出題エリア → 演出（Canvas） → ラビッドパ → UI。出題文字のフォントサイズは演出側から変更しない（scale での一時的な拡大は可）
- 60fps 維持のためパーティクル同時数に上限（例: 300、ひかえめ時 150）
- ラビッドパは `docs/character/rabidopa.js` を TS 化して React コンポーネント化（props: anim, color）
- BGM倍速は Web Audio の playbackRate で対応

## 15. 素材制作の方針

- グラフィック・サウンド素材は **Google Gemini の Web 画面をブラウザ操作して作る**。**Gemini API は使わない**（API キーや外部通信をアプリに持ち込まないため）
- 手順: `.claude/skills/gemini-assets/SKILL.md`。採用した素材は `docs/assets.md` の台帳にプロンプトごと記録する
- 置き場所: `public/assets/images/` `public/assets/sounds/`。ファイル名は英小文字のスネークケース
- ラビッドパ本体は SVG リグ（§6.6）で描くので画像素材にはしない。衣装・オーラ・背景・エフェクトなど重ねる素材を Gemini で作る
- 効果音は既存の Web Audio 合成を基本とし、合成で出しにくい声・ジングル・BGM を素材化する
