## 検証のやり方
- `npm run build`
- 自動打鍵で1プレイを回し、出題文字のサイズと出題エリアの高さを実測する（`LEARNINGS.md` の「画面の検証は…」「自動打鍵のセレクタは…」）
- 画面が収まっているかは、`.dopa-scroll` の `clientHeight` と、その最初の子の `offsetHeight × scale` を比べる。1280x720 と 1920x940 の両方で見る
- 文字の重なりは `Range.getBoundingClientRect()` の総当たりで機械的に出す（`LEARNINGS.md` に手順）
- ガチャ・デイリー・休けいは、開発サーバー上で `await import('/utils/gacha.ts')` などを直接呼んで数える。`drawGacha(data, rnd)` `applyDailyPlay(data, stats, now)` `checkBreak(minutes, now)` は乱数・日付・時刻を引数で渡せる

## 注意点
- 出題文字のサイズと出題エリア（§3）は変更不可。プレイ画面に `FitScreen` を使わないこと
- 新しいメニュー画面は `FitScreen` に入れ、操作ボタンは `footer` に渡す
- `hx-unskew` と `flex` を同じ要素に付けても並ぶように直してある（以前は打ち消されて文字とゲージが重なっていた）。自作クラスに display を書くときは注意
- プレビュー用ブラウザ（Claude のブラウザ）の保存データには、テストで入れたコイン・アイテム・装備が残っている。まっさらな状態で見たいときは localStorage の `HIGHFIVE_DOPA_SAVE_V1` を消す
- プレビューのスクリーンショットは、フェードインの途中で止まって白っぽく写ることがある（アプリの不具合ではない）。表示サイズを切り替えた直後は小さく写ることもある
- 開発サーバー（port 3000）はユーザー側で起動済みのことがある。その場合は `preview_start` ではなく `navigate` で開く
- Git Bash の heredoc は日本語や引用符が混ざると落ちる。長い置換やコミットメッセージは Write ツールでファイルに書いてから使う
